Changelog¶

All notable changes to Patrimeter are recorded here (English translation of CHANGELOG.md). Format: Keep a Changelog; numbering: semantic versioning.

3.7.0 - 2026-11-28¶

Installation¶

  • Migration: three columns for the monthly reminders (the months when an account is active); they apply with the usual update.

Added¶

  • Appearance (My account, Profile tab): an accent colour of your choice (Forest, Ocean, Dawn or Slate) and a display density (Comfortable or Compact), kept by this browser. Each colour keeps sufficient contrast in both themes.
  • Sidebar on a computer: from 1,024 pixels wide, the navigation, the current month and My account move to a column on the left; tablets and phones keep their bar.
  • Micro-animations: colours on hover, menus unfolding, messages appearing, the entry dot pulsing twice; all turned off if the system asks to reduce motion.

Changed¶

  • One icon set, with the same stroke on every page: navigation, My account, messages, challenges.
  • Report on a phone: a single action, Share the picture…, opens the phone's sharing, next to the download; cancelling says nothing, a refused share explains how to save the picture.
  • Code: the account rules and the OAuth authorization server leave their controllers for services, without any new dependency.

Fixed¶

  • The monthly update is no longer asked for (banner, highlighted Update item, reminder email) when no account is active that month: all accounts closed, or opened later.
  • CHANGELOG: the links of versions 3.5.0 and 3.6.0 lead to pages that exist.

3.6.0 - 2026-11-27¶

Changed¶

  • Redesigned Challenges page: your two statuses at the top (My level, My profile), a dial of the stars and their split by family of challenges, how far the next level and the next stage are, then the entry streak. Each challenge shows its thresholds from left to right (earned, next, later), what is already done and what is missing for the next star; its rule unfolds. Indicative benchmarks, to adapt to your situation: this is not investment advice.
  • Clearer first start: a "Step 2 of 4" thread at the top of each screen (account, security, recovery key, first accounts), without the misleading "Last step"; "Why two secrets?" tells the backup codes from the recovery key, both of which can be printed; the welcome recommends the questions, then offers the pyramid and folds the three other ways to start; a family account becomes a real choice there.
  • Family members page: each member's status for the month in words ("Up to date", "To update"), their new file dropped on their card, "Remove" folded under "More actions", and the three monthly steps. Under the choice of the view, a line says what it adds up and flags each file to update; "This account" becomes "Family's accounts", and the imported balances are counted "of the month" or "carried over".
  • CI: the test of the Docker Hub image promotion runs in every full pipeline, before any tag, and no longer only at publication time.

Fixed¶

  • Docker Hub publication: the job reads the version of the tested image with Buildah and shares its credentials with Skopeo. In 3.5.0, the registry refused it (403): the 3.5.0 image was not published, 3.6.0 replaces it.

3.5.0 - 2026-11-27¶

Installation¶

  • Docker Compose: use the Compose file from this release for the recommended configuration. The HTTP probe applies to the web service; a failed backup or verification is retried after one hour.
  • Linux: reinstalling the same archive preserves data permissions and existing secrets.

Changed¶

  • Updated the affected Symfony components to 7.4.24, which includes security fixes.
  • The account list decrypts only the latest applicable statement for each displayed balance.
  • An older Docker rebuild can no longer replace a newer build of the same release.

Fixed¶

  • An account's opening date can no longer be moved beyond the month of an existing statement.
  • Copying a property to an earlier month preserves the initial ownership share for the property and its prorated loan.
  • Viewing challenges or reading the API no longer consumes the star announcement for the next monthly entry.
  • On Linux, the 3.5 updater keeps the last confirmed entry in a verified snapshot outside backup rotation. Rollback rejects a missing or corrupt snapshot before taking the site offline.
  • Monthly reminders can be retried after a mail transport failure.
  • The calendar allows returning to the current month from next month; month and year buttons retain an accessible name that identifies their field.

3.4.1 - 2026-11-26¶

Installation¶

  • Compose: set PATRIMETER_IMAGE=docker.io/kartnico1/patrimeter:latest in the Compose .env file.
  • Opt-in publication of releases to Docker Hub, GitHub and GitHub Pages from private GitLab CI.
  • Daily system rebuilds and automatic releases for verified stable Composer security fixes.

3.4.0 - 2026-11-24¶

Installation¶

  • Demonstration mode off by default: to keep the "Try the demo" button, add DEMO_MODE=true to the settings (Settings).
  • On Linux, nginx configuration to take again (bank statements and CSV import up to 2 MB, installation wizard); with Docker, nothing to do:
# nginx configuration of the application, that of the new version, then reload of nginx
install -m 0644 /srv/patrimeter/docs/nginx/patrimeter-app.conf /etc/nginx/snippets/patrimeter-app.conf
nginx -t && systemctl reload nginx

Added¶

  • Installation wizard (/installation): on an instance still without any account (demonstration accounts aside), the sign-in page leads to it; it checks the configuration as seen from the browser (HTTPS, address of the site DEFAULT_URI, sending emails, administrator alerts), each point saying what to fix, then creates the first account (address deemed confirmed), signed in and taken to its authenticator app. Only one account can be created this way, even by two visitors at once; afterwards, the page no longer exists. The app:user:create command remains available.
  • Custom indicators: your own totals, pyramid levels and chosen accounts (each account counted once), followed every month as the net worth, with their share of the net worth if you wish; Indicators page (values of the month, change over a month, last twelve months of each), My indicators box on the Net worth page. Encrypted as the other data, they follow the export (format 4, files 1 to 3 still import) and the key rotation (indicators).
  • Reading a bank statement on an account page: the file exported by the bank (OFX or CAMT.053) gives its closing balance and its date, which fill in the statement form, to check then save; nothing is saved nor kept before. QIF or CSV file (without a balance), in a foreign currency or with several accounts: refused with a message that says what to export; XML document without DOCTYPE, nor network access (accounts).
  • "Settings" page in the documentation: changing a setting at any time, on Linux as with Docker (file to edit, service to restart), with examples (demonstration mode, email server) and the main settings, their default value and their effect.

Changed¶

  • Fully automatic updates: every Renovate merge request, major versions included, is merged on its own as soon as its pipeline is green; no more dashboard nor approval; the lock file of the PHP dependencies is refreshed every day. doctrine-bundle 3, which requires PHP 8.4, is held until 4.0.0 (docs/ci.md, in French).

Fixed¶

  • Twig 3.31.1: security fixes published on 23 and 24 November 2026 (automatic escaping, sandbox), found by composer audit.
  • CSV import above 64 KB: nginx refused it (error 413) although the application accepts 1 MB; it now follows the limit of the data import (checked by the deployment job).

3.3.0 - 2026-11-24¶

A quality release: no change to the screens or the database, nothing to do when updating.

Added¶

  • SonarQube analysis in the CI (sonarqube job): bugs, vulnerabilities, code smells, duplication and PHP coverage, against the server's quality gate; the job fails when the gate is not passed. On main and in the full pipelines (or on demand, SONARQUBE=1); server and token in the SONAR_HOST_URL and SONAR_TOKEN variables; SonarScanner pinned by its version and checksum, kept up to date by Renovate (docs/ci.md, in French).

Changed¶

  • Changelog: versions only, without an "Unreleased" section; changes are written under the version they prepare.
  • Documentation: "Linux" wherever the reader installs Patrimeter (README, home page, requirements, comments of the nginx and php-fpm files); Debian is only named for the container image and the CI, which start from it.
  • Renovate configuration migrated (dependencyDashboard becomes an object), as its dashboard asked; checked by renovate-config-validator --strict.

Fixed¶

  • Dependable load test: k6 keeps the database, the sessions and the cache in memory and turns OPcache on as in production; it measures the application, no longer the stalls of the runner's disk, which made it fail without any code difference (p95 of 0.85 to 1.5 s for a 25 ms median). Same thresholds.
  • Findings of the first SonarQube analysis: regular expressions with a non-linear running time rewritten (thousands separators, address of a Mastodon instance, base64url encoding); label of the hidden username field meant for password managers; the Data page reuses the shared identity confirmation form. The rules that contradict the W3C and the WCAG (scrollable areas reachable from the keyboard, charts described by role="img", focus on the first field of single-form pages) are set aside in sonar-project.properties, each with its reason.

Removed¶

  • "Required Debian packages" page, orphaned and outdated since the archive installation: the requirements are in installation.md, the image's packages in docker/Dockerfile.
  • 3.0.0 proposals (propositions/), delivered: they remain in the git history.

3.2.0 - 2026-11-24¶

Installation¶

  • Two supported installations: Docker (compose.yaml) or Linux, from the archive of a version; the installation from git is no longer documented. An installation made from git moves to the archive once: download the archive of this version and its checksum into /tmp, then, as root:
# New patrimeter-update, taken from the archive
ARCHIVE="$(ls /tmp/patrimeter-v*.tar.gz | sort -V | tail -n 1)"
tar -xzf "$ARCHIVE" --strip-components=1 -C /tmp --wildcards '*/docs/update/patrimeter-update.sh'
install -m 0755 /tmp/docs/update/patrimeter-update.sh /usr/local/sbin/patrimeter-update
# Update from the archive; the old folder (with .git) stays in /srv/patrimeter.previous
patrimeter-update "$ARCHIVE"

Added¶

  • Property-based tests (fast-check, a development tool): for any amount typed in the monthly entry, the field keeps exactly that amount once formatted, and the level total shows it.

Changed¶

  • "Technologies and licenses" page in the documentation: every project used, with its official site, its role and its license.
  • Same titles from one page to another: the page's name in bold, then the month in grey ("Update November 2026" on the three tabs of the monthly update, as "Budget November 2026"); the head buttons in the same format.
  • Months and years picked from a calendar: the month fields (copy of another month, an account's balance, goals) look like the month picker of the page heads ("Oct 2026"); the household's birth years are picked from a calendar of years. Without JavaScript, the text field remains.
  • Saver style offered from the first steps: the "First steps" card asks for it as long as none is chosen.
  • Clearer challenges: score in clear ("1 of 3") and, on each card, the ladder of its stars, from the first at the bottom (earned) to the last at the top, each threshold saying what it asks; total "8 stars of 28" and ladder of the six levels; the saver style is chosen in My profile; the passkey leaves the First steps (five steps), it stays in the Protected account challenge. Always with the notice "Indicative benchmarks, to adapt to your situation: this is not investment advice."
  • Level of the challenges in the net worth box ("★ Level 4: Far-sighted · 15 stars"), with a link to the Challenges page; worked out from the stars already earned, without slowing the page down.
  • No more "My assets" menu: the Accounts and Real estate buttons are at the top of the Net worth page, next to Share; the tax household opens from the Budget page.
  • Monthly update on the right of every menu, always put forward (bold, outlined); red with a dot as long as the month is not entered.
  • Budget page aligned with Savings goals: "Budget" title with the month in grey, Set up tax household and categories button at the top, a single + Enter the budget button when the month has no budget.
  • patrimeter-update installs an archive downloaded by the administrator: checksum checked, database backed up, new version installed next to the old one, migrations, restart; patrimeter-update --rollback brings back the version and the database from before. No more git, Composer or Packagist access on the server.
  • Docker: the database is backed up on every new version, even without a migration (var/backups-before-update, the latest three); compose.yaml no longer builds the image, it pulls it from the registry.
  • Installation and update documentation rewritten: requirements at the top of the page, commented commands ready to copy, without any version number to keep up to date; Release with direct links to the archive, its checksum, compose.yaml and patrimeter.env.example.
  • Security policy: direct link to report a vulnerability (confidential issue), response and fix times, coordinated disclosure.

Fixed¶

  • Delivery archive: files and folders are no longer group-writable (git archive created them as 775 and 664).

3.1.0 - 2026-11-24¶

Installation¶

  • Migrations: a table for the "to refine" balances and a column for the savings rate aimed at; they apply with the usual update. No other address nor variable: nginx and .env.local do not change.

Added¶

  • Challenges in the API and the MCP service: GET /api/v1/challenges and the get_challenges tool give the stars, the level, the saver stage and style, the entry streak and each challenge with its thresholds, with the "not investment advice" notice; described in docs/openapi.yaml.
  • Entry streak in the monthly reminder: with the challenges on, the email gives the current streak and what entering the month would bring to it (a new star or the next threshold), with the "not investment advice" notice; worked out from the months entered and the stars earned alone, still without any amount.
  • Simple questions for beginners: a fifth choice at the first sign-in, one question at a time in everyday words, with amounts by ranges, an exact amount or "No"; "Why this question?" gives the level of the pyramid concerned; the last question, optional, chooses the saver style.
  • "To refine" balances: the first balances created by the welcome pages (pyramid, express entry, questions) are marked in the monthly entry until they are saved again (approximate_statements table, without any amount).
  • "Savings rate kept" challenge: the months in a row where the budget plans savings of at least the rate the user chooses themselves on the challenge's card (from 5% to 50%, no rate suggested by default); three more stars (29 in all), also in the API and the MCP.
  • Stars and level on the report: Show my stars adds them to the card and to the shared picture, on request and without any amount (own net worth, challenges on).

Changed¶

  • More compact monthly update: an "=" button (or the = key) under each field takes the previous month's balance and moves to the next account; a level whose balances are all entered this month is folded, with its total; the change in net worth from the previous month follows the typing.

  • Updating on a single page (docs/mise-a-jour.en.md): patrimeter-update, checking and rolling back, commands commented and ready to copy; the installation points to it. Shorter README.

Fixed¶

  • k6 alone on the runner again: it now waits for every job of the test, e2e and security stages (Nuclei, added in 2.25, scanned the application during the measurement and made the p95 threshold fail without any error), and the publication of the documentation waits for it; checked by PerformancePipelineTest.
  • Net worth page as fast as in 2.26: the "First steps" card only measures its six steps, with simple queries, instead of every challenge (goals, safety cushion, streaks); it is not worked out at all once the six steps are done or the card is hidden. The other challenges are measured on the Challenges page and after the monthly entry.

3.0.0 - 2026-11-23¶

Guided first run and challenges: a new user builds their pyramid in a few minutes, then stars reward their good habits. Indicative benchmarks, to adapt to your situation: this is not investment advice.

Installation¶

  • Migration: two tables for the challenges and stars; they apply with the usual update.
  • nginx: /defis and /bienvenue join the list of the application's addresses in docs/nginx/patrimeter-app.conf (take the file again; it is part of the container image). Without it, these pages answer 404.
  • Configuration: new optional variable GAMIFICATION (true by default; false removes the challenges from the whole instance).

Added¶

  • First accounts (Net worth page, as long as no account exists): four ways to start. Build my pyramid shows the empty pyramid and its six levels: each level offers its common accounts (current account, Livret A, LDDS, PEA, life insurance…) with today's balance, and takes its colour once filled. Express entry gathers all these accounts on one page. The accounts are created together, opened this month with their balance, all or nothing; a loan is entered by its outstanding principal. The CSV import and the creation account by account remain.
  • Challenges and stars (Challenges menu): eight challenges of good habits (first steps, entry streak with one forgotten month forgiven a year, wealth up to date, safety cushion, no consumer loan, goal under way, budget kept up to date, protected account), up to three stars each; a star earned is never lost. The stars give a level from 1 to 6.
  • Saver profile: a stage computed every month (Discovery, Organized, Protected, Serene, Builder) and an optional style (Ant, Project, Home, Horizon), which only changes the order of the challenges. Neither return, nor share of a level, nor product, nor ranking between users: an architecture test checks it.
  • "First steps" card on the Net worth page: six steps with a link to each, one star each, can be hidden.
  • Stars announced after the monthly entry.
  • Challenges can be turned off by each user (Challenges page or My profile), their stars kept.

Changed¶

  • Navigation: the Challenges entry follows Monthly update; the bottom bar of a phone adapts to the number of entries.
  • Net worth page without any account: the four ways to start replace "Create a first account"; then, the "First steps" card replaces "Complete your net worth", which stays if the challenges are turned off.
  • Renovate: full image (Node, PHP and Composer already installed), without any GitHub token, every day at 3:00; the CI's Node image is looked up on Docker Hub; Buildah held below 1.44 and endroid/qr-code below 6.1 (PHP 8.4 needed); release notes not fetched.
  • Proposals of 3.0.0 (propositions/3.0.0/): ideas and mockups of the first run, the challenges and the interface.

Fixed¶

  • Test of the demonstration's writes in bursts: it takes the real elapsed time into account (unstable on a slow runner).
  • Renovate: an update of the PHP dependencies also writes THIRD-PARTY-LICENSES.md again (otherwise its merge request failed on the licenses test).
  • CI: Python stays at 3.14 (Semgrep cannot be installed with 3.15 yet) and OpenSSF Scorecard at 5.6 (5.7 answers 404 on our GitLab); Renovate no longer offers them.

2.26.1 - 2026-11-18¶

Changed¶

  • Tax household: the number of adults (one or two) and the number of children (none to 12) are chosen in two lists, and the form only shows the rows of these people, each with their first name and year of birth. The first names of the children are no longer entered separated by commas; a child keeps their budget items when their first name changes, and lowering the number of children removes the last ones of the list. From the CI archive, /srv/patrimeter-v1 is no longer taken for the extracted archive.
  • Passkey without user verification accepted by reusing the second factor's challenge.

Security¶

  • A user's data inaccessible to the others (separation in five barriers, see docs/architecture.md, in French); links sent by email built from DEFAULT_URI, never from the request's Host header.
  • Migrations written in SQL only: Doctrine's automatic schema comparison is disabled, because under SQLite it rebuilt tables and triggered cascades.
